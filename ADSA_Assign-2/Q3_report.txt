1. The procedure
----------------
RB-ENUMERATE(x, a, b)            // prints all keys k in the subtree of x with a <= k <= b, in increasing order
1  if x == NIL: return
2  if a < x.key:   RB-ENUMERATE(x.left,  a, b)
3  if a <= x.key and x.key <= b:  print x.key
4  if x.key < b:   RB-ENUMERATE(x.right, a, b)

The initial call is RB-ENUMERATE(T.root, a, b), with a <= b.
The tree is an ordinary red-black tree, so it satisfies the binary-search-tree property:
for every node x, every key in x.left is < x.key and every key in x.right is > x.key.
(Keys are distinct.)  No augmentation of the tree is needed.


2. Proof of correctness
-----------------------
Claim. For every node x (including NIL), RB-ENUMERATE(x, a, b) prints exactly the keys k of the subtree
rooted at x that satisfy a <= k <= b, each once, in increasing order.

Proof by induction on the height of x.

Base case: x = NIL. The subtree has no keys and the procedure prints nothing. The claim holds.

Inductive step: let x be a node and assume the claim for x.left and x.right (smaller height).
The keys of the subtree of x split into three groups: L (in x.left), {x.key}, R (in x.right),
and by the BST property  every key of L < x.key < every key of R.

 (i) Left subtree.  If a < x.key, line 2 recurses; by the induction hypothesis it prints exactly
     the in-range keys of L, in increasing order.
     If a >= x.key, line 2 is skipped. This is safe: every key of L is < x.key <= a, so L contains
     no key of [a, b]; skipping prints nothing that should have been printed.
 (ii) The node itself.  Line 3 prints x.key if and only if a <= x.key <= b, i.e. exactly when x.key is in range.
 (iii) Right subtree.  If x.key < b, line 4 recurses; by the induction hypothesis it prints exactly the
     in-range keys of R, in increasing order.
     If x.key >= b, line 4 is skipped. This is safe: every key of R is > x.key >= b, so R contains
     no key of [a, b].

The output is (in-range keys of L), then (x.key if in range), then (in-range keys of R).
Because L < x.key < R, this sequence is increasing, and it contains exactly the in-range keys of the
subtree of x, each once.  This proves the claim for x.

Applying the claim to the root gives the required output for the whole tree.  QED


3. Running-time analysis: O(r + log n) per query
------------------------------------------------
Let n be the number of keys, r the number of keys in [a, b] (the number reported), and h the height
of the tree.  A red-black tree satisfies  h <= 2 lg(n + 1)  (CLRS Lemma 13.1), so h = O(log n).
Every call to RB-ENUMERATE does O(1) work besides its recursive calls, so the running time is
O(number of calls).  We count the calls.

Calls on non-NIL nodes. A visited non-NIL node x is either
  (A) in range (a <= x.key <= b): there are at most r of these, because each one is printed; or
  (B) out of range.

Lemma. If x is visited and x.key < a, then x lies on the search path for a  (the root-to-node path
that an ordinary BST search for the value a would follow).  Symmetrically, if x is visited and
x.key > b, then x lies on the search path for b.

Proof. Take x visited with x.key < a, and let p be any proper ancestor of x on the path from the root.
 - If x is in the LEFT subtree of p, the call went left at p, which happens only if a < p.key.
   A BST search for a also goes left at p (a < p.key).
 - If x is in the RIGHT subtree of p, then p.key < x.key < a, so a > p.key, and a BST search for a
   also goes right at p.
So at every ancestor the path to x makes the same decision as the search for a; hence x is on that search path.
The case x.key > b is symmetric: x in the right subtree of p requires p.key < b, and the search for b
goes right; x in the left subtree of p gives b < x.key < p.key, and the search for b goes left.  QED

(Keys are distinct and a, b are fixed values, so the comparisons above are strict where claimed.)

Each search path has at most h + 1 nodes, so there are at most 2(h + 1) visited out-of-range nodes (type B).

Calls on NIL. Every call on NIL is made by a visited non-NIL node, and each node makes at most 2 calls,
so there are at most 2 * (r + 2(h + 1)) NIL calls.

Total number of calls  <=  (r + 2(h+1)) + 2(r + 2(h+1))  =  3r + 6(h + 1)  =  O(r + h)  =  O(r + log n).
Space (recursion stack) is O(h) = O(log n).

Building the tree takes O(n log n) once; it is not part of the per-query cost.
Over q queries the total time is O(n log n + q log n + R), where R is the total number of reported keys.

Empirical sanity check (not part of the proof): on 18,000 random range queries over trees of up to 5,000 keys,
the number of visited nodes never exceeded 2.0 * (r + log2(n+1)).
